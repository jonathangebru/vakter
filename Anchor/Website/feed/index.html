Threat feed · v1

The list of things you shouldn't trust.

The Vakter threat feed is a signed, daily, one-way bundle of known-bad indicators — phishing domains, scam phone numbers, Apple-impersonation sites, malicious bundle IDs, scam SMS templates. Your Mac downloads it once a day and matches against it locally. Like Apple's XProtect: pattern data, not a query API.

The contract, in one line. The feed is a public download. Your Mac fetches it, verifies the Ed25519 signature, and matches locally. Nothing about your Mac is sent back to us. There is no per-user state on the publisher side. There is no query.

1. What the feed is

§ 01 / 07

Once a day, Vakter signs a small bundle of known-bad indicators and uploads it to a public host. Your Mac downloads it on its next poll, verifies the Ed25519 signature, and unpacks it into a local cache. Every check then runs locally — "is this domain in the phishing list?", "is this number a known scam caller?" The publisher is never told what was checked.

The bundle holds eight categories: phishing domains, scam phone numbers, Apple-impersonation domains, malicious macOS bundle IDs, scam SMS templates, romance-scam patterns, package-scam templates, and a source-attribution file. Roughly 20,000 entries today, under five megabytes, fetched in a single HTTPS request once per day.

The model is Apple's XProtect — pattern data shipped to every Mac, matched locally — scoped to the threats Vakter watches for: scam calls, phishing links, fake Apple-support pages, romance scams, package-tracking impersonation.

2. What it isn't

§ 02 / 07

The category invites confusion with several other things it is not. For the record:

  • Not a real-time threat-intelligence API. There is no endpoint you call with "is example.com bad?" The bundle is a one-way download; lookup happens on your Mac.
  • Not a query service. Vakter does not transmit the domains you visit, the numbers that call you, or the messages you receive. The publisher is never asked, so it cannot log.
  • Not a network-connected analysis pipeline. Once today's bundle is on disk, every check works in airplane mode.
  • Not a cloud LLM. The feed is a flat list of strings and patterns; the model in AI features is a separate on-device system.
  • Not a fingerprint of your Mac, sent to vakter.app. The bundle simply arrives and sits on disk — there is nothing to collect.

3. The eight categories

§ 03 / 07

Nine files per bundle: one manifest.json and eight data files. The slugs are stable identifiers — adding, removing, or renaming a category requires a schema-version bump and is treated as breaking.

phishing-domains

Lowercase domains known to host phishing pages, one per line.

phishing-domains.txt
phone-numbers

E.164 numbers reported as scam robocalls, voice-phishing, or impersonation calls.

phone-numbers.txt
apple-support-fakes

Apple Support / Apple ID / iCloud impersonation domains. A separate list because the cost of mis-flagging Apple itself is high.

apple-support-fakes.txt
malware-bundle-ids

macOS CFBundleIdentifier strings for applications observed behaving maliciously.

malware-bundle-ids.txt
sms-templates

Regex patterns for scam text bodies — "your package is held", "USPS delivery failed", the standard repertoire.

sms-templates.json
romance-scam-patterns

Narrative scoring rules for messages that show the canonical romance-scam shape. Pattern data, not a verdict.

romance-scam-patterns.json
package-scam-templates

Shipper-impersonation patterns — fake DHL, UPS, FedEx, postal-service tracking, with the URL shapes that mark them.

package-scam-templates.json
sources

Per-category attribution: where each entry came from and when. The auditable paper trail.

sources.json

Each file's shape is fixed by a JSON Schema the publisher validates against before signing — a bundle that fails schema validation is never published.

4. Verify a bundle yourself

§ 04 / 07

The signature is the trust anchor. Vakter verifies it automatically whenever a new bundle arrives; you can verify it by hand the same way. Five steps on the command line:

  1. Download the bundle and signature. curl -O https://feed.vakter.app/feed-2026-05-29.tar.gz and curl -O https://feed.vakter.app/feed-2026-05-29.sig. The signature is the raw 64-byte Ed25519 signature of the tarball — not of the manifest.
  2. Fetch the publisher public key. curl -O https://vakter.app/feed/v1/key.pem. The same key ships embedded in the Vakter binary; the fingerprint is published here so the in-app value can be cross-checked.
  3. Verify the signature. openssl pkeyutl -verify -pubin -inkey key.pem -sigfile feed-2026-05-29.sig -in feed-2026-05-29.tar.gz. A passing signature returns Signature Verified Successfully.
  4. Unpack and read the manifest. tar -xzf feed-2026-05-29.tar.gz. The manifest lists every file with its sha256 and entry count — cross-check each before trusting it.
  5. Inspect the data files. Text categories are line-delimited; JSON categories are standard JSON. grep, diff against yesterday's bundle, or build your own matcher. Nothing about the feed is opaque.

Vakter runs the same steps automatically. If any one fails, the client keeps the last-known-good bundle and tries again next cycle — a bad bundle never replaces a good one.

5. Where the data comes from

§ 05 / 07

The bundle is a curated re-publication of public threat-intel feeds, with a manual review layer on top.

  • PhishTank — community-reported phishing URLs, multi-submitter-verified, filtered to domains.
  • URLhaus (abuse.ch) — open malware-URL repository. Domain-level extraction; no full URL paths.
  • abuse.ch sibling feeds (ThreatFox, MalwareBazaar) for malicious bundle-ID attribution.
  • FCC robocall complaint database — US scam-call reports, cross-checked against international equivalents.
  • Manually-curated allowlists — Apple, Google, major banks, major postal services. Each gets extra scrutiny before any related indicator ships.

The list is imperfect. Threat-intel feeds carry false positives; domains get parked and re-used; numbers get spoofed. The bundle refreshes daily, accepts that some entries will be wrong, and biases toward silence: if the feed is uncertain about an indicator, Vakter prefers to say nothing rather than cry wolf. The cost of a missed scam is real; the cost of training users to dismiss warnings is worse.

6. Versioning

§ 06 / 07

Two version axes, both visible in manifest.json.

schema_version — the shape

A small integer (semver-style; current value 1). Bumps only on breaking changes: a removed field, a renamed field, a new required field, a new closed-vocabulary value. Clients refuse a bundle whose schema_version exceeds the value they were built against, so an older app never silently mis-parses a newer bundle.

bundle_version — this bundle

A date string formatted YYYY.MM.DD, bumped once per publication. Monotonic — a client refuses a bundle that sorts earlier than the one already on disk. The rare same-day hot-fix gets a fourth segment (YYYY.MM.DD.N).

Two axes because the shape changes rarely and the content changes daily.

7. How Vakter uses it

§ 07 / 07

The feed is built for the rhythm of a normal Mac. Three rules:

  • One small download per day. Under five megabytes; the daily delta is smaller. Vakter polls on a schedule that drifts a few minutes between installs to keep the CDN flat. No streaming connection, no websocket.
  • Offline still works. The last-known-good bundle stays cached. If your Mac is offline for a week, the feed simply ages a week. Matching does not require a network round trip.
  • You can turn it off. Settings → Privacy → Threat Feed has a single toggle that disables the daily download. Anti-theft does not depend on the feed; the AI features do not depend on it; nothing breaks. Opt-out, not load-bearing.
